# Acondicionamiento de línea

Este procedimiento sirve para determinar **qué está pasando, qué se debe revisar y qué gestión corresponde** cuando un cliente informa un problema o una condición física en su instalación.

> [!IMPORTANT]
> Primero debemos separar dos cosas:
>
> * **¿El servicio funciona?**
> * **¿La instalación o algún elemento está en malas condiciones?**
>
> Un servicio puede funcionar correctamente y, aun así, necesitar un acondicionamiento físico.

---

## 1. Preguntar qué problema tiene el cliente

Primero pedir al cliente que explique qué necesita.

Por ejemplo:

* Un cable está dañado.
* La fuente está rota o deteriorada.
* La fibra está dañada.
* Un soporte está desprendido.
* Quiere cambiar de lugar el equipo.
* Quiere llevar Internet por cable a otra habitación.
* Quiere colocar otro router para mejorar el WiFi.
* El router/Host Vilo presenta una falla.
* Hay una condición que puede representar un riesgo.

**No decidir todavía qué gestión cargar. Primero identificar el problema.**

---

## 2. Identificar qué elemento está involucrado

Determinar cuál de estos elementos está relacionado con el pedido:

* **ONU:** equipo de fibra óptica.
* **Router/Host Vilo:** equipo que distribuye Internet dentro del domicilio.
* **Fuente:** alimenta eléctricamente los equipos.
* **Cable:** puede ser de red, fibra u otro cable de la instalación.
* **Soporte:** elemento utilizado para sujetar equipos o cableado.
* **Fibra óptica:** cable que lleva el servicio hasta la ONU.
* **Instalación interna:** cableado o elementos ubicados dentro del domicilio.

Si no se puede determinar qué elemento está afectado, pedir al cliente una descripción más precisa y, cuando sea posible, evidencia fotográfica.

---

## 3. Comprobar si el servicio funciona

Ahora verificar si el cliente tiene Internet.

Preguntar:

> ¿En este momento puede utilizar Internet normalmente?

Si responde **sí**, realizar una validación para confirmar que el servicio funciona.

Registrar cómo se comprobó:

* Navegación.
* Prueba de velocidad.
* Ping.
* Estado de ONU/router.
* Otra prueba disponible según el caso.

### Si el servicio funciona

Registrar:

> **El servicio se encuentra operativo. La solicitud corresponde a una condición física o de instalación.**

Continuar con el paso 4.

### Si el servicio NO funciona

No tratar el caso únicamente como acondicionamiento.

Primero realizar el **diagnóstico técnico correspondiente** para determinar si existe una falla de conectividad.

Continuar con el paso 5.

---

## 4. Determinar qué tipo de trabajo necesita

Una vez confirmado que el servicio funciona, identificar qué quiere o necesita el cliente.

### A. Quiere mover el equipo o modificar la bajada

Corresponde a:

**Cambio de bajada.**

Ejemplo:

> El cliente quiere cambiar de lugar donde está instalado el equipo.

Gestionar mediante el circuito vigente de **instalación interna**.

---

### B. Quiere colocar un cable dentro de la casa

Corresponde a:

**Cableado interno.**

Ejemplos:

* Llevar un cable de red hasta otra habitación.
* Realizar una extensión LAN.
* Llevar conexión por cable hasta un televisor o PC.

Gestionar mediante el circuito vigente de **instalación interna**.

---

### C. Quiere mejorar la cobertura WiFi

Si solicita incorporar otro router para ampliar la cobertura, corresponde evaluar:

**Servicio WiFi / Eternet Plus.**

Gestionar mediante el circuito correspondiente.

---

### D. El router/Host Vilo tiene una falla

Si el problema está específicamente en el **router/Host Vilo en comodato**, no cargarlo como instalación interna.

Corresponde gestionar:

**Reclamo por cambio de Host.**

Antes de gestionarlo, realizar las validaciones técnicas correspondientes.

---

### E. Hay algo roto, deteriorado o en malas condiciones

Ejemplos:

* Fuente dañada.
* Cable deteriorado.
* Soporte desprendido.
* Fibra exterior dañada.
* Ingreso de agua.
* Instalación en una condición insegura.
* Otro problema físico que no corresponde a una instalación interna.

Esto corresponde a:

**Acondicionamiento físico.**

Registrar detalladamente qué se observa y derivar por el circuito correspondiente.

---

## 5. Si el servicio NO funciona

Si el cliente informa que no tiene Internet, primero determinar si realmente existe una falla de conectividad.

Realizar las comprobaciones correspondientes según el servicio.

Revisar, cuando corresponda:

* Estado de la ONU.
* Estado del router/Host.
* Luces de los equipos.
* Alimentación eléctrica.
* Cables y conexiones.
* Pruebas remotas.
* Navegación.
* Ping u otras pruebas disponibles.

Registrar **qué prueba se realizó y qué resultado dio**.

### Si se confirma una falla técnica

Gestionar como:

**Falla técnica.**

No cargar automáticamente una instalación interna solamente porque se necesita una visita.

Si el problema requiere intervención de otro sector, realizar la derivación correspondiente a **Redes / Backoffice Técnico**.

---

## 6. Si funciona Internet pero hay un problema físico

En este caso separar ambas situaciones.

Ejemplo:

> La ONU funciona correctamente y el cliente tiene Internet, pero informa que la fibra exterior está deteriorada.

Registrar:

* **Estado del servicio:** funciona correctamente.
* **Problema:** fibra exterior deteriorada.
* **Gestión:** acondicionamiento físico.

Otro ejemplo:

> El cliente tiene Internet, pero quiere llevar un cable de red desde el router hasta otra habitación.

Registrar:

* **Estado del servicio:** funciona correctamente.
* **Solicitud:** cableado dentro del domicilio.
* **Gestión:** instalación interna.

---

## 7. Pedir evidencia cuando sea necesario

Si el problema es físico y puede verse, solicitar una fotografía.

La foto debería permitir identificar:

* Qué elemento está afectado.
* Dónde está ubicado.
* Qué daño o condición presenta.
* Cómo están realizadas las conexiones.

Ejemplo:

> Cliente informa que la fibra está dañada. Solicitar fotografía de la zona afectada.

Si el cliente no puede enviar una fotografía, dejar registrado:

> **No fue posible obtener evidencia fotográfica.**

No solicitar fotografías cuando no aporten información útil para determinar la gestión.

---

## 8. Registrar las pruebas realizadas

Nunca registrar solamente:

> "Se verificó."

Indicar qué se verificó y cuál fue el resultado.

### Incorrecto

> Se hicieron pruebas y funciona.

### Correcto

> Se valida navegación desde el domicilio. El servicio responde correctamente. No se detecta falla de conectividad. El inconveniente informado corresponde a una condición física de la instalación.

Esto permite que el siguiente sector entienda exactamente qué se hizo.

---

## 9. Informar costos o condiciones

Si la visita o el trabajo puede tener un costo, informar al cliente según las condiciones comerciales vigentes.

Dejar registrado:

* Si se informó que puede existir un costo.
* Si corresponde una bonificación.
* Si el importe depende de una evaluación en domicilio.
* Cualquier condición informada al cliente.

No confirmar un precio definitivo si depende de lo que determine el técnico durante la visita.

---

## 10. Antes de cargar o derivar, revisar esta lista

Antes de finalizar la gestión, asegurarse de tener:

* [ ] Qué problema informó el cliente.
* [ ] Qué elemento está afectado.
* [ ] Si el servicio funciona o no.
* [ ] Cómo se comprobó el estado del servicio.
* [ ] Qué pruebas se realizaron.
* [ ] Resultado de cada prueba.
* [ ] Descripción de la condición física.
* [ ] Fotografía o evidencia, cuando corresponda.
* [ ] Tipo de trabajo que necesita.
* [ ] Costos o condiciones informadas al cliente, cuando corresponda.
* [ ] Circuito correcto para gestionar el caso.

---

# 11. ¿Qué gestión corresponde?

Utilizar esta guía rápida:

| Situación                                                    | Gestión                                     |
| ------------------------------------------------------------ | ------------------------------------------- |
| Quiere mover la instalación                                  | **Cambio de bajada / Instalación interna**  |
| Quiere cablear otra habitación                               | **Cableado interno**                        |
| Quiere ampliar la cobertura WiFi                             | **WiFi / Eternet Plus**                     |
| El Host Vilo está fallando y corresponde reemplazo           | **Reclamo por cambio de Host**              |
| Hay una fuente, soporte, fibra o elemento físico deteriorado | **Acondicionamiento físico**                |
| No tiene Internet y se detecta una falla                     | **Reclamo técnico**                         |
| El problema requiere intervención de otro sector             | **Derivación a Redes / Backoffice Técnico** |

---

# 12. Ejemplo completo

### Cliente

> "Tengo Internet, pero la fibra que está afuera está dañada."

### Paso 1 — ¿Tiene Internet?

**Sí.**

### Paso 2 — ¿Qué está afectado?

**Fibra óptica exterior.**

### Paso 3 — ¿Es una falla de conectividad?

**No. El servicio funciona.**

### Paso 4 — ¿Es una instalación interna?

**No. El problema está en el exterior.**

### Paso 5 — ¿Qué corresponde?

**Acondicionamiento físico.**

### Paso 6 — ¿Qué registrar?

> Cliente informa daño visible en fibra óptica exterior. Se valida que el servicio se encuentra operativo. No se detecta falla de conectividad. Se solicita evidencia fotográfica de la condición informada y se deriva por el circuito correspondiente para evaluación/intervención técnica.

---

# Regla principal

> **Primero identificar qué está afectado. Después comprobar si el servicio funciona. Finalmente determinar qué gestión corresponde.**

No cargar una instalación interna solamente porque el caso requiere una visita.

La gestión debe definirse por **el elemento afectado + el trabajo necesario + el estado del servicio + el circuito correspondiente**.
